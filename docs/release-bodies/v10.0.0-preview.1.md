InfoCarrier.Core puts an Entity Framework Core `DbContext` on the client of a multi-tier application. This release is a rewrite for EF Core 10, and it is not compatible with `3.1.1`.

## Breaking

- No Remote.Linq and no Aqua. The expression serializer is in-tree, and the only dependency is `Microsoft.EntityFrameworkCore`.
- `net10.0`, not `netstandard2.0`. A .NET Framework client has to be ported first.
- One package became two: `InfoCarrier.Core` for the client and the server, `InfoCarrier.Core.AspNetCore` for the server endpoint.
- `UseInfoCarrierClient` is now `UseInfoCarrier`, and the namespaces collapse to `InfoCarrier.Core`.
- The client contract is async only. `3.1` carried sync and async pairs, and the sync half was usually implemented by blocking.
- `IInfoCarrierValueMapper` changed shape. `TryMapToDynamicObject` and `TryMapFromDynamicObject` are now `TryMapToWire` and `TryMapFromWire`, in `InfoCarrier.Core.ValueMapping`.

Your `DbContext` and your entity classes carry over unchanged. Everything around them moves. The three public interfaces kept their names and changed their shapes on purpose, so an old implementation fails to compile rather than compiling and misbehaving.

## New

- A transport ships. `HttpInfoCarrierTransport` on the client, `app.MapInfoCarrier()` on the server. `3.1` shipped neither, so every application wrote its own.
- A security boundary, stated and tested. Your server runs an expression tree that arrived over the network. Deserialization is default-deny over node kinds, types and methods, no assembly is loaded to satisfy a payload, reflection entry points are blocked, and the payload size is bounded before parsing. The written review names the weaknesses that are accepted rather than solved. `3.1` had nothing to say about this.
- Complex types, and JSON-mapped owned collections.
- `ExecuteUpdate` and `ExecuteDelete`.
- Many-to-many without an explicit join entity.
- Savepoints. `3.1` had begin, commit and rollback only.
- Compiled models.
- Blazor WebAssembly, published trimmed.
- Symbol packages and SourceLink, so you can step into the provider from a debugger.

## Verified

The provider runs Microsoft's own EF Core specification suite, the same suite the SQL Server, SQLite and InMemory providers run.

```
Total tests: 22658, Passed: 22472, Failed: 9, Skipped: 177
```

The nine are known, classified, and gated in continuous integration so the number cannot grow unnoticed. Each is written up on the limitations page in terms of the code that triggers it. Skipping a test to make the suite green is forbidden here.

## Install

```sh
dotnet add package InfoCarrier.Core --version 10.0.0-preview.1              # the client and the server
dotnet add package InfoCarrier.Core.AspNetCore --version 10.0.0-preview.1   # the server endpoint
```
