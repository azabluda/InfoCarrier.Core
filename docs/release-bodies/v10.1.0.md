This release makes a relational backing store a first-class case.

- `FromSql` and `Database.SqlQuery<T>` reach the server's database. Both halves have to agree, and the server's half denies by default.
- `EF.Functions`, your own `HasDbFunction` mappings, `AsSplitQuery` and `UseRelationalNulls` cross the wire. A store's own function family is named on both halves, with `AddInfoCarrierAllowedTypes` and `AllowTypes`.
- Table per hierarchy, table per type and table per concrete type round trip, and so do table splitting and entity splitting.
- `GetTableName()` and `Model.GetRelationalModel()` answer on a client context, built from your own `[Table]` attributes and `DbSet` names.
- Three shapes of query that used to return an answer now throw, with EF Core's own wording. `UseNonRelationalServerStore()` turns them off where the server's store is not relational.
- Nothing was removed from the public API. Verified against Microsoft's EF Core specification suite: 29516 tests, 19 known failures, gated in CI.

```sh
dotnet add package InfoCarrier.Core              # the client and the server
dotnet add package InfoCarrier.Core.AspNetCore   # the server endpoint
```
